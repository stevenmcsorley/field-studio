Updated 2026-10-30. Reference: OP–1 field OS 1.7.3+1 and manual 1.7.0. **Field Studio is a working independent reconstruction; exact feature, visual and sonic parity are not established.** It uses original DSP and graphics. Firmware inspection did not recover executable engine code or display assets. There is no reference device for controlled sound or interaction comparisons. Matching names and exposed controls do not prove matching algorithms, parameter ranges or results.

In this ledger, *implemented* means code provides a concrete function; *validated* means a named test exercises the stated behaviour. Neither word means equivalent to the manufacturer's implementation. The final Linux four-target CTest run and native editor/screenshot checks pass; exact hardware equivalence remains unverified.

## Explicit hardware substitutions

FM radio reception/transmission and OB–4 tuning require RF hardware. Embedded motion sensing needs an actual host sensor or an explicitly labelled substitute. Battery, charging, speaker/headphone circuitry, USB host/device identity and device-specific BLE behaviour are outside this software implementation. A host audio/MIDI interface is an equivalent access path, not an emulation of these circuits/protocols.

## Evidence required to close parity gaps

For an exact sound claim, use a known engine/preset, parameter state, note/velocity/input and recording chain, then compare time/envelope/spectral behaviour with a reference device or controlled source. Public musical demos with unknown processing cannot establish numerical parity. For visual parity, compare every engine/effect/LFO/sequencer/tape/browser/settings page at known control states, not one attractive screenshot. Record source/time/state and remaining uncertainty for each comparison.

Official photographs/PDF renders in the sibling research directory are analysis references, not packaged application assets. The application contains original graphics and algorithms. `reference-controls.json` records documented labels in software enum order, not recovered engine equations or a factory preset bank.

All four Linux CTest targets pass after the DBox, dedicated sequencers, album and editor updates. Expanded core ASan/UBSan passes after moving large test instances to the heap. ## Envelope and import compatibility pass

T2 synth/melodic-sample ADSR is tested with a constant sample: attack midpoint/peak, decay-to-sustain, sustain hold, release midpoint and silence. Shift+T2 now provides Poly/Mono/Legato/Unison, overlapping mono/legato glide, pitch-bend range and patch gain. Tests verify mono last-key fallback, legato envelope continuity/glide progression, independent poly notes and four-voice detuned unison; project/slot state persists the settings. String now uses fractional-delay pitch handling for bend/glide. Amp remains a continuous-input model; unsupported note-envelope/play-mode controls are disabled there. Exact hardware response curves, mode semantics and visual identity are not established.

Sample import now restores supported OP-1 melodic markers/root pitch and drum-kit regions, tuning, gain/pan/direction and closest available play mode. Legacy mono12-second and stereo20-second marker profiles are explicit; ambiguous long mono kits are rejected rather than scale-guessed. Unsupported fades/routing/FX/LFO/envelope values remain attached, with COM import details. Known modeled synth presets select a software engine but explicitly do not claim original preset-sound reproduction. Unknown engines leave the current sound unchanged. Synthetic end-to-end preset tests and all24 ordinary WAVs in the official Snaps pack import successfully; the pack is not bundled.
