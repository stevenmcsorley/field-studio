# AIFF/AIFC preset metadata import

`Source/PresetFormat.cpp` is an independent, control-thread-only parser. It reads IFF container structure and the JSON carried by an `APPL` chunk with four-byte signature `op-1`. Audio decoding remains the responsibility of JUCE's audio file reader. Successful metadata parsing is not a claim that the audio encoding, factory patch sound, or DSP parameter ranges have been reproduced.

Container rules were checked against Apple's *Audio Interchange File Format AIFF-C*, draft1991-08-26, especially file structure and Application Specific Chunk sections, available as an [archived primary specification](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/AIFF/Docs/AIFF-C.9.26.91.pdf). Application signature and JSON field evidence comes from independently reading the local public research fixtures; no community implementation code is used by this parser.

`readMetadata(file,error,rawPayload)` returns the original parsed object with every unknown JSON property intact. The optional raw payload preserves exact bytes following `op-1`, including NUL/space padding. Missing metadata and ordinary non-AIFF files return void with an empty error; recognized malformed AIFF/AIFC containers and malformed metadata return void with an explanatory error. File access failures are errors. An untyped JSON object can be returned for inspection but `isPreset` requires a nonempty string `type`.

`engineIndex` maps known melodic `type` strings to the software enum. DBox maps to the dedicated software drum-engine index 14; unknown types and sample-kit drum metadata return -1, and callers must not silently choose a known synth for them. The metadata reader itself performs no DSP conversion. The wrapper now applies supported sample markers, root tuning and drum-pad fields through `PresetMapping`; modeled synth macro/envelope/FX/LFO integers are still retained without guessed conversion. Such conversion needs independently established ranges and semantics. The raw source metadata should remain attached to the imported project if exact future re-interpretation is desired.

The parser validates all chunk bounds, the full declared FORM boundary, odd-size zero padding, and APPL signature length. Unknown chunks/signatures are skipped. It rejects extra bytes outside a single FORM, duplicate `op-1` chunks, oversized metadata (>1 MiB), excessive chunk count (>100000), invalid UTF-8, trailing JSON values/garbage, unescaped string control bytes, non-padding after a NUL terminator, and nesting deeper than 64. Numeric tokens are limited to 18 integral digits, 128 characters total and exponent magnitude 280 before JUCE parsing, to avoid unsupported or overflowing numeric representations. These are explicit implementation limits; it does not fully validate mandatory audio chunks, sample counts or codecs.

`tests/preset_tests.cpp` generates its own binary fixtures for valid AIFF/AIFC, padding/order variations, raw/unknown-field preservation, engine mapping and malformed-input limits. Optional command arguments `<fixture-root> <fixture-inventory.json>` compare all selected public fixture metadata objects independently against the research inventory. The fixture collection is not bundled in the instrument.

Validation on 2026-10-30: the shared Release test executable passed the synthetic container/JSON/unknown-field/engine-map suite and independently matched the metadata from all 167 selected public research fixtures (`fixture-inventory.json`, source-root `references/te-op1`). This verifies the metadata reader against those files; it does not establish hardware patch sound reproduction or universal preset compatibility.

## Sample-patch compatibility pass

`PresetMapping` now applies supported sample settings before committing the import. Melodic `sampler` patches use the six-second Q15 start/loop-in/loop-out/end positions and `base_freq` for the sampler root pitch. Drum `type: drum` patches select the drum sampler and import all24 regions; unused regions are silent. Supported profiles are legacy mono12-second markers (4058 units per44.1kHz reference frame) and stereo20-second Q31 markers, corroborated against primary community format implementations. Ambiguous long mono kits are rejected rather than scale-guessed. Per-pad tuning, level, pan and reverse are applied within the software ranges; gate/choke options are approximate and unsupported fades/transient/channel routing remain in source metadata. COM → Import details records limitations.

Plain audio and sampled presets use neutral sampler ADSR/FX/modulation defaults; master mix settings are retained. Original hardware ADSR, FX and LFO numeric values are not converted into assumed timing/equations. Known modeled synth preset types select the corresponding software engine, with an explicit message that the exact patch sound is unsupported; unknown engines fail without replacing the current sound. Source metadata, import report, mapped regions and root pitch persist with projects/patch slots.

Independent format references: [libop1 marker conversion](https://github.com/padenot/libop1/blob/master/src/op1_drum_impl.cpp), [chirashi stereo marker writer](https://github.com/g-lok/chirashi/blob/main/internal/engine/encoder_op1.go), and [Field per-key metadata research](https://github.com/jstnfst/te-op1/blob/main/public/drum-keys.js). Only format facts are used; these implementations were not copied into the app.

Validation: synthetic AIFF files containing actual audio plus APPL metadata pass end-to-end drum region/tuning/reverse, melodic root/trim, save/reload/unknown-property and unsupported-engine preservation tests. All167 earlier metadata fixtures still pass the metadata-reader checks. The official [Snaps sound pack](https://teenage.engineering/downloads/op-1/sound-packs) was downloaded to the research directory: all24 WAV files import successfully. That pack is ordinary audio, so this confirms real sample-file decoding, not universal OP-1 preset compatibility. It is not redistributed with the app.
