# Continuous audio design — phase 6 migration

Status: original audit2026-10-30; staged foundations implemented2026-10-31. See AUDIO_REWRITE_PROGRESS.md. The live tape/controller ownership migration and dropout-free acceptance remain unimplemented. Preserve the user's phase order; stages 2–5 may change these boundaries before this plan is implemented. Sources inspected: `Source/Engine.{h,cpp}`, `Source/PluginProcessor.{h,cpp}`, `Source/PluginEditor.cpp`. No runtime contention benchmark or future-fix test was run.

## Current failure and ownership

`FieldProcessor::processBlock` uses `ScopedTryLock(engineLock)` and clears the output when acquisition fails, incrementing `skippedBlocks`. That prevents a blocking wait, but converts any long control operation into audio loss. `makeState` holds this lock while packing every sample, all eight tapes/four tracks, albums and preset state. Compression follows outside the lock, so moving compression alone cannot solve the dropout. `exportAudio` obtains `engine.exportMix()` under the lock. `restoreState` parses much of its input before locking, but resampling banks, preparing engine and copying sample data still happen after locking.

`Engine::Track` owns mutable planar vectors; `tracks()` exposes both mutable and const arrays. Processor `selectTape`, restore and state serialization directly move/copy/read them. Editor timer reads durations through `tracks()`, obtains waveform arrays and sequencer/pad state while holding the same lock. Sample drawing reads Engine vectors directly. Editor control callbacks directly mutate Engine under that lock. Engine's sampler voices record positions/bounds, but read global `sampleL/sampleR/sampleSr`, rather than retaining the asset they started with. Existing `loadSample` calls allNotesOff and copies/sanitizes vectors: making only the final assignment asynchronous would still invalidate release-tail sample lifetime.

`setRecording(true)` snapshots the entire selected Track, then reserves `sr*360` frames in each channel; `selectTrack` also reserves when recording. At 48 kHz one six-minute stereo float capacity is 138,240,000 bytes (131.84 MiB); at 192 kHz it is 552,960,000 bytes (527.34 MiB). Reserving is off the audio callback today, but holds the lock and does not pre-touch physical pages. Callback vector resize may also zero a large gap after seeking: absence of allocator calls alone is not a bounded-work guarantee. Album and sample capture have analogous mutable-vector lifetime/snapshot problems. Undo currently deep-copies Track data, even for split/clear. Merely swapping vectors moves destruction of the old capacity to whichever thread releases it.

## Smallest coherent redesign

Make the audio thread the only owner of Engine's live DSP, voices, transport and mutable capture writers. Keep immutable media/document roots separate from that runtime. Remove public `engineLock`, public `engine` access and mutable `tracks()` from the Editor API. A private control-thread mutex may protect job scheduling or project labels, but must never be acquired by the callback or protect data the callback reads unsafely.

Use four boundaries rather than a second independently mutable Engine:

1. `PreparedSample` / `PreparedProject`: worker validates, decodes, sanitizes, resamples to the current host rate, constructs waveform summaries and prepares every asset outside audio. Include `requestId`, `baseRevision` and `sampleRateEpoch`. Retain existing limits and check combined memory before allocating, not merely per-channel decoded length. Job cancellation and revision conflict leave current playback intact.
2. `RtCommand`: fixed-size tagged commands through bounded SPSC queues; a single coordinator is producer if GUI, host and workers originate actions. Include compact transport/pad/sequence/mixer operations and asset handles, never vectors, ValueTrees, strings or callbacks. `tryEnqueue` returns busy on the control side; callback drains a fixed budget per block. Reserve capacity for stop/panic. Sample-accurate MIDI stays on audio's existing event path. Parameters remain cached atomics; project parameter restore is a coherent prepared parameter array, not `replaceState` inside audio.
3. `AudioDocument`: immutable sample assets and tape/album roots plus audio-owned recording overlays. `Engine::commitPrepared(handle)` validates epochs and exchanges prepared roots at a block boundary with bounded work. Full-project replace has a defined transport policy; no call to `prepare`, allocation, resample, APVTS notification or deep destruction there. A later message-thread acknowledgement mirrors parameters/UI/host state. Until acknowledgement, UI says loading. Reject obsolete loads rather than commit a stale-rate asset.
4. `ReadSnapshot` and `UiSnapshot`: audio publishes fixed POD meter/playhead/sequence/pad telemetry; Editor paints its most recent complete snapshot. Peak arrays are generated from immutable media in a worker, keyed by revision. Audio publishes a document generation for saves/export/undo, with immutable asset handles and bounded transport/parameter metadata. Worker encodes and writes that exact generation while audio continues. Snapshot request/acknowledgement has no callback wait.

### Tape and recording are the unavoidable storage change

A moved vector is suitable for loading a finished sample; it does not allow coherent concurrent save during an overdub. Do not call a worker-side full copy a snapshot while callback writes the source. Replace tape audio storage (also album/capture where concurrently saved) with fixed-size stereo pages, e.g. 4096 frames, a bounded persistent radix tree and lengths/cuts metadata. Treat published pages as immutable. The audio writer owns a working root, copying a shared page and bounded tree path from a preallocated, pre-touched pool on its first write after publication. Depth is fixed by the six-minute maximum; callback cost then depends on frames/pages touched, never the tape's duration. New unwritten pages start as zero; seek updates logical length without filling a vector-sized gap. Keep cuts immutable and prepare edited cut lists in the worker.

The callback must not copy a whole page table on every snapshot or modify a container retained by the worker. Node/page ownership counts, reclamation and tree operations need explicit bounded implementations. Allocate and pre-touch the writer reserve/pool on the worker before an acknowledged RecordReady command. Pool exhaustion stops recording with a visible error and keeps already recorded material/playback; it never silences the whole block, waits, or falls back to heap allocation. Instrument and prove worst-case page consumption for reverse/fast overdub and frequent saves. A worker can replenish the reserve from retired generations. Set a hard byte cap including pages pinned by saves/history; bound retained generations and reject/defer extra saves under pressure. Six-minute reserve must therefore become a prepared recording resource, not the current locked vector reserve.

Undo/redo and heavy lift/drop/clear produce prepared immutable root revisions; split changes metadata only. A worker edit carries base track revision and range. If ongoing recording changes that revision, reject/rebase explicitly; never replace recent overdubs with a stale result. Enqueue commits only after the edited root is ready. A fixed short output crossfade can hide a deliberate discontinuity at an edited boundary; use a bounded old/new reader transition with explicit playhead mapping. Do not render two complete instruments for an entire load, discard MIDI, or replace output with cached blocks.

### Asset lifetime and retirement

Give each sampler voice an immutable sample handle and capture its sample rate, root note, loop bounds and pad settings at trigger. Existing voices finish against that asset when a new sample is loaded; new notes use the new asset. Preserve unaffected voices/DSP state on tape edits. For a full-project reset, define a bounded fade/release policy and admit its audible behaviour instead of promising preservation of unrelated old notes. Tape/album roots remain retained while old/new readers or a save refer to them.

Do not assume `atomic<shared_ptr>` is lock-free, or allow the last shared_ptr decrement to destroy megabytes on audio. Use an indexed preallocated handle registry with explicit producer/audio/snapshot ownership, lock-free publication verified for the target atomics, and an audio-to-worker retirement ring. Capacity/backpressure must guarantee retirement publication cannot fail: do not consume another prepared commit without reserved retirement space. Worker performs recursive destruction, vector freeing and file cleanup after audio acknowledgement/epoch quiescence. Shutdown cancels workers, stops the callback, then drains handles in that order.

## Concrete API migration

- Engine: replace `loadSample(const vector&,...)` with prepared immutable handle install; expose `captureUi(UiSnapshot&) noexcept`, `applyCommand(const RtCommand&) noexcept`, `publishSnapshot(SnapshotSlot&) noexcept`. Keep pure DSP methods and fixed voice storage. Replace `Track::left/right`, `sampleLeft/right` exposure and `tracks()` with private page readers/asset handles. Provide worker-side flattening only for serialization/export.
- Processor: retain host `prepareToPlay` as a lifecycle boundary; prepare scratch/output/stem buffers and RT queues there. Version host rate with an epoch; cancel/rebuild old prepared jobs on change. Replace locked `selectTape`, transport edits, capture/album starts, sample/patch/project load with command/job submission and completion status. Separate `decodeState -> PreparedProject`, `commitPrepared`, and `encodeSnapshot`; never call broad `restoreState` from audio. Keep disk writes atomic via the current temporary-file path.
- Host state: `getStateInformation` may be called on unusual host threads. Return a complete cached serialized acknowledged generation immediately if called on audio; expose pending/cached revision. Non-audio callers may wait for bounded snapshot acknowledgement and encode off audio, but if callbacks are suspended obtain a lifecycle-owned snapshot without waiting for an impossible acknowledgement. Document whether a host save includes the newest in-flight recording block. `setStateInformation` stages data and schedules a prepared commit, never mutates live vectors. Avoid stale cached state silently pretending to include newer audio.
- Editor: replace direct Engine calls with `submitControl`, `requestEdit`, `requestImport`, `requestExport` and `latestUiSnapshot`; render prepared waveform summaries. All status/error text belongs to control/UI state. A long worker job never owns an audio-visible lock.

Implement in that order within phase 6: establish exclusive ownership/queues and telemetry, immutable sample lifetime, paged tape/capture plus snapshots, prepared editing/project commit, then host save semantics and stress gates. A halfway queue conversion retaining direct Editor vector access is unsafe.

## Required acceptance evidence

These are proposed gates, not tests already passed:

- Run real `FieldProcessor::processBlock` continuously at 44.1/48/96/192 kHz and 32/64/512-frame blocks while separate threads repeatedly save, export, load validated large projects/samples, switch tapes, edit, undo and request waveforms. Use a deterministic nonzero DC tape/input pilot in addition to notes so an entire unexpected zero block is unambiguous. Assert no unrequested all-zero block, no skipped callbacks, monotonic callback count and finite output. Test album playback and all stem channels too. Silence legitimately present in musical content alone is a weak dropout detector.
- Instrument callback entry/exit and allocator/deallocator, lock acquisition, file access and ownership release. Assert zero callback allocations/frees, blocking/try locks, waits, joins or I/O, including first record after load, far seek + overdub, undo and final voice release. Report callback duration distribution and worst case against block deadline; non-real-time CI timings cannot prove device-level glitch freedom.
- Verify each saved snapshot has a single committed revision with matching parameter/mixer/media metadata; hash immutable pages before/after concurrent recording and serialization. Confirm stable saved generations while live hashes advance; restore/offline-render the saved generation against its expected oracle. Use TSAN on threaded queue/page tests and ASAN/UBSAN on malformed state and repeated lifetime turnover. Include revision conflict, cancellation, rate-epoch mismatch, retirement saturation and shutdown during save.
- At RecordReady, exhaustively fault pool/queue capacity and check graceful rejected job or stopped recording, preserved output and recoverable state. Long seeks must touch only bounded pages. Measure total pinned memory with full tape banks, max sample, albums, seven history versions and simultaneous export/save; enforce cap without dropping a callback.
- Hold a long sampler note while repeatedly swapping differently sized/rated samples. Verify the old voice's rendered hash/lifetime against its immutable original asset, new notes against the new one, and no use-after-free. Check block-boundary commit and bounded transitions for audible step size; uninterrupted nonzero audio alone does not establish click-free editing.


## Follow-up audit after tape/MIDI passes

Historical audit: besides `engineLock`, the old keyboard handoff took JUCE's internal lock and incoming CC handling notified host listeners synchronously. The2026-10-31 foundation pass replaces both paths; the main engine lock remains. An eventual no-lock callback must replace GUI keyboard injection with bounded events and defer own parameter-notification mirrors using revisions that preserve newer host automation.

Append-only chunks suffice for sample/album capture, but arbitrary seek/reverse overdub needs bounded COW tape storage. A concrete candidate is4096-frame stereo pages (32KiB), a fixed-depth64-way persistent tree, prefaulted page/node reserves and worker reclamation of generation-tagged handles. Save snapshots retain document roots; subsequent recording writes copy only affected pages/nodes. Do not copy entire page tables or use callback-side final shared_ptr destruction. Missing sparse pages read as zero, avoiding unbounded gap zero-fill after a seek. A full memory budget must include live media, history, pinned save generations, pending imports and writer reserves; pool exhaustion must defer/reject work or explicitly stop recording while keeping playback alive.

Production Editor reads/writes must migrate to owned telemetry slots and commands. Leaving the public mutable Engine/tracks API in use while removing its lock would introduce data races. Preserve offline DTO/fixture helpers for tests, but test live state through prepared-document commits and immutable snapshots.

Host state calls are a separate constraint: even copying a cached complete state into getStateInformation's host-owned MemoryBlock can allocate and copy large amounts. Do not claim arbitrary host state calls are realtime-safe. The firm target is a bounded processBlock; state I/O needs a documented non-realtime host-call assumption or an explicit external-reference/cached-generation policy.

Acceptance requires continuous nonzero audio plus MIDI while imports/saves/exports/edits/undo/bank swaps occur, stable saved generations during overdub, old sample-voice lifetime, revision/epoch/pool-failure safety, no callback allocation/free/lock/wait/file access, and timing/sanitizer stress checks. The current implementation does not satisfy this gate.
